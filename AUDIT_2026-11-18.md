## Security controls verified in source
- Role checks on admin endpoints and protected student/employer resource routes.
- Employer ownership checks when viewing/updating job applications.
- CV selection requires ownership of the CV by the applying student; a snapshot is persisted when applying.
- JWT verification pins HS256 and checks session version; password changes invalidate old session versions.
- HttpOnly, Secure-in-production, SameSite=Lax cookie, no-store auth responses, and same-origin mutation checks on the Next.js proxy.
- Only Verified company / Active / unexpired internships appear in public listings.
- Job closure uses a soft close, preserving applications and recruitment history.
- Password hashes use bcrypt. Admin cannot be registered by the public registration API.

## Findings requiring follow-up (do not claim these are fixed)
- **Password recovery not implemented**: forgot-password returns 503 with a truthful message, and no outbound email recovery exists.
- **Admin navigation active indicator**: admin sidebar currently always applies selected styling to Dashboard even on Companies/Students/Reports. Improve client-side current-route highlighting.
- **Rate limit architecture**: Express rate limiting is process-local and can reset on Render Free restarts; reverse-proxy IP attribution must be verified in the actual hosting path.
- **Public job field constraints**: although this audit fixed malformed field types, field-specific length/shape limits should be added and exercised against abusive payloads.
- **CSRF**: origin and fetch-metadata checks exist, but missing-Origin and non-browser-client scenarios warrant a threat-model review and authenticated tests.
- **Upload expectations**: CV import supports text/Markdown files, not actual PDF parsing; PDF is available via print/save. Do not describe this as native PDF upload support.
- **UI/browser**: cross-device dropdown clipping, responsive layouts, keyboard navigation and color contrast require browser-based visual verification; source inspection is insufficient.
- **Deployment parity**: Vercel deployments and GitHub CI are visible, but the Render workspace/service branch and backend SHA were not independently confirmed in this audit.
- **Secrets/database privileges**: production secret entropy, Atlas user least privileges, GitHub/hosting MFA, and historical exposed demo-password reuse require owner-side checks. No secrets were read or displayed.

## 19 November follow-up: password recovery and dependency advisory scan

- Added dedicated `server/src/controllers/passwordResetController.js` endpoints:
  `POST /api/auth/forgot-password` and `POST /api/auth/reset-password`.
  Reset tokens are cryptographically random (32 bytes), stored as SHA-256 digests,
  expire in 15 minutes, and are claimed atomically. Successful resets rehash passwords
  with the existing User model pre-save hook and increment `sessionVersion`.
- Recovery responses intentionally avoid indicating whether an email belongs to an
  active account. Invalid/expired tokens cannot reset a password. Failed email delivery
  invalidates its token. Add rate limiting for both recovery routes.
- Added same-origin Next.js proxy for reset submission, `/reset-password` UI,
  and truthful `/forgot-password` form feedback.
- Optional sender integration uses Resend's API; no email provider credentials
  were added, and email recovery remains **unavailable** until the owner
  configures `RESEND_API_KEY`, `PASSWORD_RESET_FROM`, and a valid
  `PASSWORD_RESET_BASE_URL` in the backend environment.
- Added reset regression tests and refreshed deployment/example configuration;
  default JWT expiry in sample files matches the seven-day code default.
- Added a report-only production dependency advisory scan to GitHub CI.
  Its results must be inspected rather than assuming no advisories.
- Render service deploy parity, browser accessibility/mobile tests, runtime
  email delivery, and credential/Atlas least-privilege checks remain unverified.
